# 小程序部分优化 - 测试点

> 需求来源：禅道 STORY #255164（代账合规-20261029）；材料不涉及接口，仅功能测试点。

## 需求一：财赢消息-往来挂账提醒，触发规则优化（增加判断其他应收款、其他应付款）

设计方法：判定表法（权限×六类科目×账期×频次控制的组合）+ 边界值分析（账期 12 个月边界）+ 错误推测法。

| 编号 | 测试点 | 方法 | 优先级方向 |
|---|---|---|---|
| 1-1 | 仅其他应收款存在期限>12个月条目、其余科目无 → 结账触发挂账提醒（新增维度独立命中） | 判定表 | P1 |
| 1-2 | 仅其他应付款存在期限>12个月条目、其余科目无 → 结账触发挂账提醒（新增维度独立命中） | 判定表 | P1 |
| 1-3 | 六类科目（应收/应付/预收/预付/其他应收款/其他应付款）均无>12个月条目 → 不触发 | 判定表-负向 | P1 |
| 1-4 | 存量逻辑回归：仅应收/应付/预收/预付存在>12个月条目、其他应收/应付无 → 仍触发（新逻辑不误伤存量） | 判定表-回归 | P2 |
| 1-5 | 账期边界：其他应收/应付款条目账期=12个月不触发，=13个月触发 | 边界值（离点/上点） | P2 |
| 1-6 | 企业未启用往来对账权限，即使其他应收/应付款存在>12个月条目 → 不触发 | 判定表-负向 | P2 |
| 1-7 | 同一会计月度多次结账 → 只发第一次，不重复发送 | 场景法-备选流 | P1 |
| 1-8 | 当天企业维度已发送过挂账提醒 → 再次满足条件不重复发送 | 场景法-备选流 | P1 |
| 1-9 | 多类科目同时存在>12个月条目（其他应收+其他应付+应收等）→ 只发送一条挂账提醒 | 判定表-组合 | P3 |
| 1-10 | 重分类场景：其他应收款贷方余额（重分类计入其他待付款方向）存在>12个月条目 → 按重分类口径正确判断触发 | 错误推测 | P3 |

## 需求二：小程序往来页面，切换属期应能查到数据（修复"暂无数据"）

设计方法：场景法 + 等价类划分（目标属期有数据/无数据两类）+ 错误推测法。作用对象为小程序往来页面全集（待收款/其他待收款/待付款/其他待付款/待开票/待收票），逐类验证不复制用例。

| 编号 | 测试点 | 方法 | 优先级方向 |
|---|---|---|---|
| 2-1 | 往来页面切换属期到有数据的属期 → 正常展示该属期数据而非"暂无数据"（覆盖六大往来页面） | 场景法-基本流 | P1 |
| 2-2 | 切换属期到确实无数据的属期 → 展示"暂无数据"空态（空态逻辑不被误改） | 等价类-无效类 | P2 |
| 2-3 | 切换属期后再切回原属期 → 数据恢复展示 | 场景法 | P2 |
| 2-4 | 切换属期后头部统计信息（客户数、总金额）与列表数据联动一致 | 场景法 | P2 |
| 2-5 | 连续快速切换属期 → 数据不串页、加载态正常 | 错误推测 | P3 |
| 2-6 | 切换到非最新结账月属期 → 列表只读 + 底部「去最新结账月开始对账」存量逻辑不被属期切换优化误改 | 错误推测-回归 | P3 |
