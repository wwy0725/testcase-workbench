# 财赢App账号及权限管理统一收归 — 测试点 1

> 需求来源：需求文档 + 《财赢App产品信息-App功能全集-10月新版.csv》（功能全集来源，权限逻辑以 CSV 为准）
> 权限生效逻辑（贯穿全流程）：**权限生效公式 = 企业业务资格 ∩ 功能自身规则 ∩ 角色授权**
> - **企业业务资格** = 授权码（有无 FPKJ_QYZK 等）/ 白名单（是否在 manage_jchgz_ds 等）/ 业务范围（是否在基础账/经营账/合规账业务范围）——决定该功能在功能树中**是否存在**
> - **功能自身规则** = CSV 中的「权限规则」列（可配置 / 不可配置）——决定该功能是否**允许企业端配置**
> - **角色授权** = 管理端给角色勾选的功能范围——决定该功能对特定角色**是否可见**
> - **端差异**：App 端与小程序端的功能入口展示范围可能不同（CSV「上线端」列），需分别验证

### 1.2 功能树节点出现逻辑（企业业务资格判定）

**功能树节点出现 = 企业有对应业务资格（授权码/白名单/业务范围 任一命中）**

| 编号 | 测试点 | 验证内容 |
|------|--------|----------|
| B1 | 授权码命中（FPKJ_QYZK） | 有 FPKJ_QYZK 授权 → 查发票(开票清单/收票清单/发票移交/发票更新/开票抬头/发票分析) 在功能树展示 |
| B2 | 授权码未命中（FPKJ_QYZK） | 无 FPKJ_QYZK 授权 → 查发票相关功能不展示 |
| B3 | 授权码命中（YQDZ_DZZP） | 有 YQDZ_DZZP 授权 → 查档案(财税数字档案) 在功能树展示 |
| B4 | 授权码命中（DZPT_QY_HGZS） | 有 DZPT_QY_HGZS 授权 → 控风险(数智合规/查上下游) 在功能树展示 |
| B5 | 白名单命中（manage_jchgz_ds） | 在白名单内 → 电商合规服务(合规指引/合规证据链/电商开票/店铺管理) 在功能树展示 |
| B6 | 白名单未命中 | 不在白名单内 → 相关功能不展示 |
| B7 | 业务范围命中（基础账） | 在基础账业务范围内 → 票夹/查数据(查税金/查报表/查往来/查档案) 在功能树展示 |
| B8 | 业务范围命中（经营账） | 在经营账业务范围内 → 经营账(我的填报/我的看板) 在功能树展示 |
| B9 | 多种业务资格并存 | 同时有多种授权/白名单/范围时，对应功能都展示，无冲突 |
| B10 | 无任何业务资格 | 无任何授权/白名单/范围时，功能树为空（或仅展示通用功能） |

### 1.3 功能可配置性判定（功能自身规则）

**功能可配置性 = CSV「权限规则」列 + 企业业务资格，两者共同决定**

| 编号 | 测试点 | 验证内容 |
|------|--------|----------|
| C1 | 可配置功能 | CSV 标记「可配置」且企业有业务资格 → 功能树中可勾选 |
| C2 | 不可配置功能 | CSV 标记「不可配置」→ 功能树中展示但**不可勾选**，不可通过管理端控制该功能的角色可见性 |

| C4 | 有资格但不可配置的功能 | 有业务资格但 CSV 标记不可配置 → 展示但置灰不可勾选 |

## 三、批量设置逻辑

> **核心规则（用户明确要求补充）**：**可批量设置的功能 + 机构在业务控制的白名单内 → 才可批量设置**
> 即：CSV 中标记「可批量设置」的功能，其批量设置操作需要满足两个条件：
> ① 功能在功能树中标记为可批量设置（CSV「可否批量设置」列）
> ② 机构在对应业务控制点范围内（有对应授权码 或 在对应白名单内 或 在对应业务范围内）
> 如果功能虽然标记可批量设置，但机构不满足业务控制点要求，则无法批量设置该功能。

| 编号 | 测试点 | 验证内容 |
|------|--------|----------|
| F1 | 可批量设置的功能支持批量配置 | CSV 标记可批量设置的功能（如查数据、办业务等），机构可选择多个企业批量配置 |
| F2 | 不可批量设置的功能不支持批量 | CSV 标记不可批量设置的功能（如聚合收票、合规测算、服务确认函等），无法批量操作 |
| F3 | 批量设置需机构在业务白名单内 | 功能虽标记可批量设置，但机构不在对应业务控制点白名单内 → 无法批量设置 |
| F4 | 批量设置效果验证 | 批量设置后，所有目标企业的功能树/权限配置同步更新 |
| F5 | 批量设置与单个设置的差异 | 批量设置的权限修改对单个企业重新设置后，批量设置的效果被覆盖 |

## 四、权限生效验证（App端/小程序端）

> **权限生效 = 企业业务资格 ∩ 功能自身规则 ∩ 角色授权**
> 同时需验证 App 端与小程序端的表现差异（CSV「上线端」列标记）

| 编号 | 测试点 | 验证内容 |
|------|--------|----------|
| G1 | 企业有资格+角色勾选 → App 端可见 | 有业务资格且角色勾选的功能，登录 App 后对应角色可见 |
| G2 | 企业有资格+角色未勾选 → App 端不可见 | 有业务资格但角色未勾选 → 登录 App 后不可见 |
| G3 | 企业无资格+角色勾选 → App 端不可见 | 无业务资格（如无 FPKJ_QYZK 授权），即使角色勾选了也无效（因功能树无此节点，无法勾选） |
| G4 | 端差异验证（仅App） | CSV 标记「仅App」的功能（如票夹、聚合收票、电商合规、经营账等），小程序端不展示 |
| G5 | 端差异验证（App+小程序） | CSV 标记「App+小程序」的功能，两端都展示 |
| G6 | 不可配置功能对所有角色展示一致 | CSV 标记「不可配置」的功能（如经营账的我的填报/我的看板、我的-企业信息），所有角色可见性一致，无法按角色区分 |
| G7 | 「仅企业可配置」功能在机构端不可配置 | CSV 标记「仅企业可配置」的功能（如找资料、学财税等），机构端功能树中展示但不可勾选 |

## 五、授权到期行为（修正）

> **重要修正**：授权到期后，**管理端的功能树中该功能仍然展示、仍可配置**（因为功能树展示由业务资格判定，授权到期不影响功能树配置）。
> 只是 **App 端和小程序端的用户无法进入该功能**（入口可能仍展示，但点击后被拦截或数据为空）。
> 具体表现为：
> - 管理端功能树：授权到期后功能树**仍展示**该功能，仍可配置角色权限
> - App 端：用户登录后，虽然入口可能展示，但**无法进入**（点击被拦截或数据为空）
> - 小程序端：同 App 端，**无法进入**

| 编号 | 测试点 | 验证内容 |
|------|--------|----------|
| H1 | 授权到期后功能树仍展示 | FPKJ_QYZK 授权到期后，管理端功能树中查发票相关功能**仍展示**，仍可配置 |
| H2 | 授权到期后 App 端无法进入 | 授权到期后，App 端用户点击查发票相关功能入口，**无法进入**（被拦截或数据为空） |
| H3 | 授权到期后小程序端无法进入 | 授权到期后，小程序端用户点击查发票相关功能入口，**无法进入** |
| H4 | 续费后功能自动恢复可用 | 授权续费后，App 端/小程序端用户可正常进入该功能 |
| H5 | 部分授权到期不影响其他功能 | FPKJ_QYZK 到期不影响 DZPT_QY_HGZS 控制的功能（数智合规）正常使用 |
