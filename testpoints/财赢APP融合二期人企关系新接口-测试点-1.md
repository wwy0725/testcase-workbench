# 财赢APP融合二期人企关系新接口 — 测试点

> 需求来源：17work 文档 257263「财赢APP融合二期」第 2 节「外部团队提供的能力」（经营账/基础账场景表）+ 第 3 节「通用组件能力」（eiam 能力表 + 新表 DDL + 三方数据汇合场景示例）
>
> **范围界定**：新接口为给基础账/经营账调用的纯接口（包一层 EIAM 接口转发封装），**只出接口用例，不出功能用例**。新接口 URL 文档标注「待提供」，不捏造 URL，URL 反查用例（硬规则 4）本期待 URL 确定后补充。
>
> 本期与老 EIAM 通用服务的区别点：**appId、platformCode 不需要外部传，代码里指定**（appId=74323799365384202609041712684，platformCode=DZ）。
>
> 数据层约束：新表 `cy_app_customer_employee_relation`（人企关系关联表，source：财赢 CY / 基础账 BASE_DZ / 经营账 BUSINESS_ACCOUNT）、`cy_app_customer_open_record`（企业开通记录表，sync_source 同上）。

## H3 接口

### H4 初始化eiam企业（包装 RPC：InitFacade#initTenant，platformCode=DZ 代码指定）

| # | 测试点 | 设计方法 |
|---|---|---|
| 1 | 不传 appId/platformCode 初始化企业时按代码指定值初始化成功，EIAM 租户 platformCode=DZ、开通记录落 cy_app_customer_open_record（sync_source=调用方来源） | 等价类-有效类 + 场景法基本流 |
| 2 | 重复初始化已初始化的企业时幂等不产生重复租户/重复开通记录 | 错误推测-重复调用幂等 |
| 3 | 外部传参 appId/platformCode 时不透传覆盖，以代码指定值为准 | 错误推测-转发保真 |
| 4 | EIAM 初始化返回异常时新接口透传错误不吞错，本地不落开通记录 | 错误推测-异常透传 |
| 5 | 企业标识为空或不存在时返回参数错误 | 等价类-无效类（P4） |

### H4 加员工（经营账 addEmployeeByTenantAndAccount / 基础账 addEmployee / 通用 batchAddEmployee）

| # | 测试点 | 设计方法 |
|---|---|---|
| 1 | 基础账加员工同步成功，EIAM 创建员工，新表落 source=BASE_DZ | 场景法基本流 |
| 2 | 经营账加员工同步成功，新表落 source=BUSINESS_ACCOUNT | 场景法基本流 |
| 3 | 批量加员工（batchAddEmployee）全部员工同步成功，角色覆盖员工0/老板1/财务2 在线角色全集 | 等价类-有效类 + 边界值 |
| 4 | 重复添加同一手机号员工时幂等，不产生重复人企记录、EIAM 无重复员工 | 错误推测-重复提交（知识库：幂等提示已存在） |
| 5 | 批量中含手机号不满足 UC 规则的员工时该条跳过记错误日志，其余员工正常同步（单条失败不影响批量） | 错误推测-容错（知识库：手机号不合法跳过+错误日志） |
| 6 | 加员工分别传在线角色 0/1/2 时按传入角色同步，EIAM 与新表角色一致 | 等价类-有效类逐值 |
| 7 | 加员工传非法角色值（如 9）时报参数错误不落库（在线角色有效域 0/1/2） | 等价类-无效类 |
| 8 | 企业未初始化 EIAM 时加员工失败并明确提示（不自动补初始化） | 错误推测-前置依赖缺失 |
| 9 | 批量入参为空列表/单条/大批量的边界处理 | 边界值 |
| 10 | EIAM 加员工返回异常时透传错误，本地不落数据或与 EIAM 状态一致 | 错误推测-异常透传 |

### H4 删员工（经营账 deleteEmployeeByTenantAndAccount / 基础账 cancel）

| # | 测试点 | 设计方法 |
|---|---|---|
| 1 | 基础账删员工时 EIAM 删除员工，新表对应记录逻辑删除（is_delete=1），source=BASE_DZ 保留 | 场景法基本流 |
| 2 | 经营账删员工时同步删除，来源标记 BUSINESS_ACCOUNT | 场景法基本流 |

| 4 | 重复删除已删除员工时幂等处理 | 错误推测-重复调用 |
| 5 | 同一员工存在多来源（BASE_DZ/CY/BUSINESS_ACCOUNT）人企记录时删除只影响调用方来源记录 | 因果图/判定表-数据汇合交叉场景 |
| 6 | EIAM 删除返回异常时透传错误，本地状态与 EIAM 一致 | 错误推测-异常透传 |

### H4 空间解绑企业（重点逻辑改动：现状解绑删除人企关系 → 方案改为只解绑企业、不批量删除人企关系）

| # | 测试点 | 设计方法 |
|---|---|---|
| 1 | 解绑空间后新表人企关系记录全部保留（is_delete 不变），验证与老行为（解绑即批量删除）的差异 | 场景法 + 状态迁移-核心改动验证 |
| 2 | 解绑后查询企业绑定的人员列表仍返回原人企关系数据 | 场景法-改动下游影响 |
| 3 | 解绑后重新绑定/初始化企业时原人企关系继续生效、不产生重复记录 | 场景法-回归路径 |
| 4 | 重复解绑已解绑的企业时幂等 | 错误推测-重复调用 |
| 5 | 解绑时 EIAM 返回异常透传不吞错 | 错误推测-异常透传 |

## 待确认假设清单（与开发对齐）

1. 初始化/加员工等接口外部重复传 appId/platformCode 时以代码指定值为准（不透传覆盖）
2. 企业未初始化 EIAM 时加员工/删员工/添加组织是报错提示，不自动补初始化
3. 删员工在多来源（同一手机号多条 source 记录）时只删调用方来源记录，不动其他来源
4. 空间解绑企业后人企关系保留，查询人员列表仍可见；重新绑定后原关系直接生效
5. 加员工角色有效域沿用在线角色 0/1/2，非法值报参数错误；下线角色 3-6 是否改绑员工待确认（财赢侧老逻辑是自动改绑员工 0）
6. 手机号不满足 UC 规则被跳过的员工是否落新表 cy_app_customer_employee_relation（影响查询人员列表预期）
7. 批量加员工单批上限（财赢老逻辑 30 上限已取消，新接口是否有上限待确认）
8. 查询企业列表的"主体"维度（企业/机构区分）返回字段结构待接口设计完善后核对
