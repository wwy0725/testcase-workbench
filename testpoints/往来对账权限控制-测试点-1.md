# 财赢2026年10月迭代

## 【财赢企业端】往来对账权限控制

> 来源：庄周产品稿 mockupId=123564（branchId=1596，【26年10月】往来对账权限控制）
> 需求概述：财赢企业端权限设置在「查往来/往来对账」下新增「操作权限：对账操作」开关；企业端小程序往来对账页面、对账明细页（当前结账月/历史月）按该开关控制对账操作的展示与可用性。
> 逐类验证说明：六大往来模块（待收款/其他待收款/待付款/其他待付款/待开票/待收票）的页面表现一致，测试点不按模块复制；逐类验证范围在对应测试用例的 `前置条件:` 中体现（"覆盖 待收款/其他待收款/…/待收票"），测试数据需支撑六类模块。

### 模块一：权限设置（配置端）

| 编号 | 测试点 | 设计方法 | 优先级 |
|---|---|---|---|
| 1.1 | 勾选「查往来/往来对账」时显示「操作权限：对账操作」开关，且默认勾选 | 判定表法（条件：查往来勾选 × 对账操作显隐） | P1 |
| 1.2 | 「对账操作」开关下方说明文案展示：「开启后，企业可在小程序上进行往来对账操作；不开启，企业只能查看往来明细，不能进行核对操作。」 | 等价类划分（文案正例） | P3 |
| 1.3 | 取消勾选「对账操作」并保存：「查往来/往来对账」保持勾选，仅关闭对账操作，小程序不支持对账操作，往来明细展示不受影响 | 判定表法（合法组合规则） | P1 |
| 1.4 | 未勾选「查往来/往来对账」时「操作权限」区域隐藏，对账权限同时失效 | 判定表法（非法/依赖组合规则） | P1 |
| 1.5 | 重新勾选「查往来/往来对账」后「操作权限」恢复显示且默认勾选 | 状态迁移法（显隐状态回迁） | P2 |
| 1.6 | 保存成功后权限配置生效并同步至企业端小程序 | 场景法（基本流：配置→保存→小程序生效） | P1 |
| 1.7 | 7 类角色（老板/员工/财务/销售/采购/库管（收货）/老板（发货））对账操作配置相互独立，互不影响 | 等价类划分（角色枚举逐类覆盖） | P2 |
| 1.8 | 修改勾选后不保存直接退出，重新进入配置保持原状 | 错误推测法（未保存退出） | P3 |
| 1.9 | 保存失败（网络异常）时配置不生效并给出提示，原权限不变 | 错误推测法（提交异常） | P4 |
| 1.10 | 快速连续切换「查往来/对账操作」勾选后保存，以保存时刻最终状态生效 | 错误推测法（重复/快速操作） | P4 |

### 模块二：往来对账页面（企业端小程序）

| 编号 | 测试点 | 设计方法 | 优先级 |
|---|---|---|---|
| 2.1 | 已开启对账操作（现有逻辑回归）：六大往来模块展示状态标签「待对账/已暂存/已对账」及操作入口「去对账」「查看」 | 回归 + 判定表法（开启 × 元素展示） | P1 |
| 2.2 | 已开启且对账中：按钮文案由「去对账」变为「继续对账」 | 状态迁移法（合法转换：待对账→已暂存） | P2 |
| 2.3 | 未开启对账操作：操作入口仅展示「查看」，点击进入只读明细页 | 判定表法（关闭组合规则） | P1 |
| 2.4 | 未开启对账操作：状态标签（待对账/已暂存/已对账）不展示 | 判定表法（关闭组合规则） | P2 |
| 2.5 | 未开启对账操作：六大往来模块（待收款/其他待收款/待付款/其他待付款/待开票/待收票）及往来明细数据正常展示 | 判定表法（往来明细展示不受影响） | P1 |
| 2.6 | 权限由开启切换为关闭后，企业端重新进入页面时状态标签与操作入口按新权限更新 | 场景法（备选流：权限变更同步） | P2 |
| 2.7 | 权限关闭后企业端用户退出重新登录小程序，仍无对账操作入口 | 错误推测法（登录态/缓存绕过） | P3 |
| 2.8 | 关闭对账操作前已暂存的对账数据，重新开启后可继续对账且数据保留 | 场景法（数据保留校验） | P2 |

### 模块三：对账明细页-当前结账月（企业端小程序）

| 编号 | 测试点 | 设计方法 | 优先级 |
|---|---|---|---|
| 3.1 | 已开启对账操作（现有逻辑回归）：顶部卡片、卡片标签、提醒文案、处理记录、操作按钮、底部操作栏（同步上期/暂存/对账完成）均正常展示 | 回归 + 判定表法 | P1 |
| 3.2 | 未开启对账操作：顶部卡片与卡片标签（待对账/已暂存/已对账）不展示 | 判定表法（关闭组合规则） | P1 |
| 3.3 | 未开启对账操作：提醒文案替换为「如对款项有疑问，请联系服务顾问」 | 判定表法（差异化文案） | P2 |
| 3.4 | 未开启对账操作：处理记录不展示 | 判定表法（关闭组合规则） | P2 |
| 3.5 | 未开启对账操作：操作按钮（已收款/坏账处理等）不展示 | 判定表法（关闭组合规则） | P1 |
| 3.6 | 未开启对账操作：底部操作栏（同步上期/暂存/对账完成）不展示 | 判定表法（关闭组合规则） | P1 |
| 3.7 | 未开启对账操作：只读明细页内无任何核对/处理/暂存类操作入口，仅可查看明细 | 错误推测法（只读越权入口） | P1 |

### 模块四：对账明细页-历史月（过往账期）（企业端小程序）

| 编号 | 测试点 | 设计方法 | 优先级 |
|---|---|---|---|
| 4.1 | 已开启 + 历史月未对账/未暂存（现有逻辑回归）：无顶部卡片、无处理记录、底部有「去最新结账月开始对账」 | 回归 + 判定表法 | P2 |
| 4.2 | 已开启 + 历史月对账完成/已暂存（现有逻辑回归）：有顶部卡片（已对账标签+处理时间）、有处理记录、无底部操作栏 | 回归 + 判定表法 | P2 |
| 4.3 | 未开启 + 历史月未对账/未暂存：顶部卡片、处理记录、底部「去最新结账月开始对账」均不展示 | 判定表法（关闭组合规则） | P1 |
| 4.4 | 未开启 + 历史月对账完成/已暂存：顶部卡片、处理记录、底部操作栏均不展示 | 判定表法（关闭组合规则） | P1 |
