# 测试点：【财赢APP】服务模块接入人资业务工具

## 功能点 1：人事服务卡片展示

**设计方法**：判定表法（身份 × 人资企业白名单 → 卡片展示）+ 等价类划分（白名单有效/无效类）+ 错误推测法

> 判定依据（腾讯文档《财赢App产品信息》App功能全集行 76-79）：业务控制点 = 人资企业白名单 manage_rzywyh，判定逻辑按企业Id；模块配置：上线端仅App、业务人资、身份企业、权限规则不可配置、不可批量配置、默认初始角色企业老板

| 编号 | 测试点 | 方法 | 优先级倾向 |
|---|---|---|---|
| 1-1 | 企业Id在人资企业白名单（manage_rzywyh）内的用户（企业身份）进入服务板块，展示「人事服务」卡片及 4 个应用占位，应用单行平铺 | 等价类-有效类 + 需求正例 | P1 |
| 1-2 | 企业Id不在白名单内的用户进入服务板块，不展示人事服务卡片，其余服务模块不受影响 | 等价类-无效类（判定表负向格） | P1 |
| 1-3 | 仅财赢业务企业不展示人事服务卡片（存量规则不被本需求误改） | 判定表-负向格 + 存量回归 | P2 |
| 1-4 | 白名单企业用户的服务板块中，人事服务卡片与代理记账/财税合规等存量模块共存且互不影响 | 场景法-基本流 | P2 |
| 1-5 | 机构身份登录是否展示人事服务卡片（产品信息表配置身份=企业，预期不展示，仍待确认） | 判定表-待确认格 | P3 |
| 1-6 | 人事服务卡片内应用占位点击可进入对应应用（应用范围待业务方分析，验证占位可交互） | 需求正例 | P2 |
| 1-7 | 人资业务数据接口异常/超时，服务页不白屏、有兜底表现 | 错误推测-接口异常 | P4 |
| 1-8 | 人事服务卡片应用数据为空时的空态表现 | 错误推测-空数据 | P4 |
| 1-9 | 白名单按企业Id判定：同企业不同企业身份账号展示一致（企业级粒度非账号级） | 边界/粒度验证 | P3 |

## 功能点 2：服务板块红点提醒

**设计方法**：状态迁移法（应用红点：无→有→点击→消失；tab 红点：随应用红点联动）+ 场景法（下发→查看→点击→消失全路径）+ 错误推测法

| 编号 | 测试点 | 方法 | 优先级倾向 |
|---|---|---|---|
| 2-1 | 人资业务下发消息后，消息指定的应用图标显示红点，服务 tab 同步显示红点 | 需求正例（状态迁移：无→有） | P1 |
| 2-2 | 点击红点指定的应用，该应用红点消失 | 需求正例（消失规则） | P1 |
| 2-3 | 多个应用同时有红点时，点击其中一个应用，仅该应用红点消失，其余应用红点保留，tab 红点保留 | 状态迁移-部分迁移 | P1 |
| 2-4 | 服务页面下所有应用红点都消失后，服务 tab 红点消失 | 需求正例（tab 联动） | P1 |
| 2-5 | 红点消失后人资业务再次下发消息，红点重新出现 | 状态迁移-重复触发 | P2 |
| 2-6 | 已点击消除红点的应用，退出页面/杀进程重开 App 后红点不复活（状态持久化） | 错误推测-持久化 | P3 |
| 2-7 | 消息下发时用户未在线/未打开 App，下次打开后红点补显 | 错误推测-离线补显 | P3 |
| 2-8 | 快速连续点击带红点的应用，红点仅消失一次，无重复处理异常 | 错误推测-重复点击 | P4 |
| 2-9 | 非人资业务用户服务板块及服务 tab 无本需求红点 | 判定表-负向格 | P3 |
| 2-10 | 切换账号后红点状态不串号（按账号隔离） | 横切维度-多账号 | P2 |
| 2-11 | 多设备登录时红点状态跨端一致（状态存服务端） | 横切维度-多端/功能类型-消息通知 | P3 |
| 2-12 | tab 红点在人事服务之外来源存在时按聚合规则联动（聚合来源全集待确认） | 横切维度-聚合来源 | P3 |
| 2-13 | 同一消息重复下发时红点状态收敛（去重不闪烁） | 横切维度-时序并发/功能类型-消息通知 | P4 |
