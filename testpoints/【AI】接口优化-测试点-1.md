## H3 接口

### H4 查发票（合并 cy/invoice/getInvoiceStaticMarkdown + /cy/invoice/getRelationCustomerInvoiceStatisticMarkdown）

| # | 测试点 | 设计方法 |
|---|---|---|
| 1 | 传必填 startdate/enddate 查询时返回发票明细合计+销项发票明细+进项发票明细，Markdown 表结构与字段与文档示例一致，原"发票统计"整块不再返回，入参正确透传两个底层接口 | 场景法基本流 + 格式校验 |
| 2 | 一般纳税人账套返回五类合计行：销项（本月开票）/进项（本月收票）/进项已认证（本月）/近三年未认证/红字，各行总份数/总金额/总税额/总价合计与底层数据一致 | 等价类-有效类 + 出参映射验证 |
| 3 | 小规模账套返回两套口径合计行：销项（普+专）/进项（本月收票），与一般纳税人口径区分 | 等价类-账套类型 |
| 4 | 销项（本月开票）口径为"仅剔除作废发票"：红冲/异常但未作废的发票仍计入，与原"正常"口径对比验证 | 口径转换验证（P1 核心） |
| 5 | 进项（本月收票）口径：按开票日期所在月聚合统计、剔除作废发票，与"进项已认证（本月）"（按认证口径）区分互不混算 | 口径转换验证（新增口径，P1 核心） |
| 6 | 近三年未认证行展示开始日期/结束日期（近三年区间），其余合计行该两列展示"-" | 格式/字段映射 |
| 7 | relationtype=kh 时：一般纳税人只返回销项（本月开票）合计行、只返回销项发票明细，无进项类内容 | 判定表-合法组合 |
| 8 | relationtype=gys 时：只返回进项（本月收票）合计行、只返回进项发票明细 | 判定表-合法组合 |
| 9 | relationtype 不传时默认查全部：销项+进项合计行与明细全部返回 | 判定表-默认分支 |
| 10 | relationcustomernamelist 传企业名称列表时明细按意图识别的企业名称过滤返回 | 等价类-有效类（透传验证） |
| 11 | 销项发票明细按价税合计降序排列并取前100条；恰好100条全返回、101条截断为100条 | 边界值（上点） |
| 12 | 明细商品列先按销方（购方）名称分组、组内按【货物、应税劳务及服务】"*"内名称聚类（如 *现代服务*LT板→现代服务），份数/金额/税额/价税合计为分组后合计 | 业务规则映射 |
| 13 | period（否）传与不传均正常返回，不传时按默认属期兜底（发票统计历史口径：属期空取最新自然月，与 glossary 结账月兜底口径的归属需确认） | 等价类-可选参数 + 默认值 |
| 14 | URL 反查（完整网关路径）：查询 /xmanage-compliance/cy/invoice/getInvoiceStaticMarkdown、查询 /xmanage-compliance/cy/invoice/getRelationCustomerInvoiceStatisticMarkdown | 硬规则4-URL反查 |
| 15 | 底层发票接口返回空数据时返回空表格占位（"-"）不报错、不输出残缺表头 | 错误推测-兜底 |
| 16 | startdate/enddate 必填缺失、relationtype 传非法值（非 kh/gys）时返回参数校验错误或按明确规则处理 | 错误推测-无效等价类 |
| 17 | relationcustomernamelist 传不在机构关联企业名单中的企业名称（往来企业信息表 ads_cy_hg_relation_customer_df 无有效记录）时返回空明细不报错 | 错误推测-无效等价类（知识库：关联企业来源表） |

### H4 查往来（合并 /hggj/reconciliation/queryReconciliationListMarkdown + /cy/finance/analysis/getIntercourseDetailByTypeMarkdown）

| # | 测试点 | 设计方法 |
|---|---|---|
| 1 | 传 period+statisticsType=0 时返回数据说明+往来合计+往来明细，六个往来类型齐全，Markdown 结构与文档示例一致，入参正确拆分透传两个底层接口 | 场景法基本流 + 格式校验 |
| 2 | statisticsType 分别传 1/2/3 时返回季报/半年报/年报对应数据 | 等价类-有效类逐值 |
| 3 | statisticsType 不传时默认按月报（0）处理 | 等价类-默认值（文档矛盾待确认） |
| 4 | dealingsTypeList 传 [1,2] 时只返回应收/应付两个类型的合计与明细 | 等价类-有效类（过滤透传） |
| 5 | dealingsTypeList 不传时六个往来类型全部返回 | 判定表-默认分支 |
| 6 | 查询属期大于最大结账期时只返回最大结账期数据（数据说明属期显示为最大结账期） | 口径验证（P1 核心） |
| 7 | 往来合计行的对账状态与对账完成时间按底层实际状态正确展示，状态枚举映射正确（底层状态码 0未完成→待对账、1已暂存→已暂存、2已完成→已对账） | 出参映射验证（知识库：对账状态码） |
| 8 | 往来明细行账款/最长账期/往来类型中占比（%）正确，占比=账款/该往来类型总金额 | 出参映射验证 |
| 9 | period 传年（YYYY12）时按年报属期返回 | 边界值-年属期 |
| 10 | URL 反查：查询 /hggj/reconciliation/queryReconciliationListMarkdown、查询 /cy/finance/analysis/getIntercourseDetailByTypeMarkdown | 硬规则4-URL反查 |
| 11 | 底层返回空数据/某往来类型无数据时空值展示"-"、无该类型段落或空表格不报错 | 错误推测-兜底 |
| 12 | period 必填缺失/非法格式、dealingsTypeList 传非法值（如 7）时返回参数校验错误或明确处理规则 | 错误推测-无效等价类 |
| 13 | 意图识别查询往来且未对账时推送对账卡片（AI 对话链路联调验证） | 场景法备选流（提示性） |
